> Working draft · Initial site copy based on my public project.


Teaching knowledge does not arrive as a clean database. It lives in manuals, personal notes, movement cues, student history, and an instructor's judgment.

In Pilates Studio OS, I am starting with the domain model: movements, equipment, cues, relationships, and teaching standards. The database foundation and initial movement library come before the retrieval layer and lesson-planning application.

This order makes the product questions more concrete. Which movement record does a cue belong to? Which equipment does it require? What context should an instructor review before choosing it? Which relationships are stable enough to store?

The planned AI workflow will need that structure. A polished generated lesson would not prove that it used the right context.

My takeaway: making domain knowledge explicit is product work, not merely preparation for a model.
